# Rokid Relay v0.1.15-preview.27

Release type: preview refinement
Date: 2026-07-08

## Highlights

- The glasses-confirmed recovery status introduced in preview.26 now carries a freshness notion. While the link is up and the glasses have reported in, the row keeps the definitive green **"Armed on the glasses — they recover on their own"**. When the phone is only showing a report remembered from an earlier session, the row says so: **"Armed on the glasses — last confirmed 2h ago"** — still green, but honest about its age, so a factory-reset or swapped pair of glasses can no longer hide behind a stale confirmation forever.
- Partially broken glasses reports are no longer swallowed. If the glasses say they are armed but the recovery key or the `WRITE_SECURE_SETTINGS` grant is missing, the row calls it out — **"Glasses report settings grant missing — tap Re-arm"** (or key missing, or both) — instead of falling back to the phone's own optimistic "Recovery armed".
- Tapping Re-arm now shows what is happening: while a wireless bootstrap is in flight, its progress replaces the "tap Re-arm" prompts and the remembered "Recovery armed" text instead of being masked by them.
- The phone now asks the glasses for a forced state report as soon as the link is ready for messages. Previously the helper deduplicated its report per link session, so after a phone-side app restart (with the glasses never seeing a disconnect) no fresh report ever arrived and the row stayed on the stale wording despite a live link.

## Notes

- Precedence in the fallback row is now: disable pending → bootstrap in progress → recovery armed → bootstrap complete → last bootstrap error → setup hint. Value and tone are decided together, so an armed device stays green even with the relay enabled, a completed-bootstrap record, or a stale error from an old failed attempt.
- "Live" means a report was received during the current link session; the flag resets whenever the link drops.
- No glasses helper changes in this release; the bundled helper stays at `0.1.10-preview.13` / vc23.

## Verification

- Phone unit tests pass, covering: live vs stale green (with 2h/just-now/missing-timestamp ages), key/grant/both-missing broken reports, broken report without phone-local provisioning, broken and disarmed prompts yielding to an in-flight bootstrap, disable-pending priority, and the fallback precedences (armed over relay-enabled, over bootstrap-complete, over stale error).
- On real hardware: cold-started app before the link came up → green "Armed on the glasses — last confirmed …" from the persisted report; once the bridge became operational the forced report arrived (persisted timestamp refreshed) and the row switched to the live "Armed on the glasses — they recover on their own".

## Test Focus

- With everything armed, open the app before starting the relay: the row should show "Armed on the glasses — last confirmed … ago". Start the relay: it should switch to "Armed on the glasses — they recover on their own" once the glasses report in.
- Revoke the helper's `WRITE_SECURE_SETTINGS` grant on the glasses, reconnect, and confirm the row reads "Glasses report settings grant missing — tap Re-arm".
