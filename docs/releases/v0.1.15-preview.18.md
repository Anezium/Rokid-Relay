# Rokid Relay v0.1.15-preview.18

Release type: preview reliability + UX update
Date: 2026-07-05

## Highlights

- Fixes the self-arm Wireless Debugging bootstrap that received the glasses pairing code but never completed, leaving recovery unprovisioned. Three stacked defects are resolved:
  - The bootstrap worker could fail silently: a throwable before the first pairing log was swallowed and its reason was overwritten by later glasses status messages. Every step now logs under a single `RelaySelfArmWireless` tag, failures always surface with a stacktrace, and the reason is kept in a dedicated last-error field.
  - A stale in-flight flag could permanently block retries. The trigger now uses an attempt id with a watchdog timeout, resets on every terminal path, supersedes a stale attempt when a new pairing token arrives, and ignores the resend tail once complete.
  - The on-glasses bootstrap script aborted before granting: under `set -e` it tripped on an unwritable `adb_keys`, and once that was relaxed a trailing `adbd` restart dropped the Wireless Debugging session mid-read. The script is reduced to its essential outcome — grant `WRITE_SECURE_SETTINGS`, confirm it, and fail only if the grant did not take — and never touches adbd ports or restarts it.
- Makes the bootstrap foolproof for a non-technical user:
  - Gates on Wi-Fi up front. If the phone has no Wi-Fi LAN address, the flow no longer starts a doomed attempt; it shows `Connect this phone to Wi-Fi first — the same network as your glasses — then tap Bootstrap.`
  - Replaces raw automator state codes on the Self-arm recovery row with short, actionable sentences (setting up the glasses, reading the code, pairing, timed out, expired, failed).
  - States the one-time prerequisites before the user acts: the row reads `Not set up — put phone and glasses on the same Wi-Fi, then tap Bootstrap`, and the notice line spells out the full setup.
  - Clarifies the manual pairing-code field as an "only if asked" fallback so novices are not misled into typing when the flow is automatic.
- Stops leaking the full ADB shell command (which embeds the recovery public key) in the bootstrap failure exception.

## Test Focus

- With the phone Wi-Fi off, tap Bootstrap on the Self-arm recovery row and confirm the flow refuses to start with the plain "connect to Wi-Fi" message instead of failing deep in pairing.
- With phone and glasses on the same Wi-Fi and the Relay Accessibility service enabled on the glasses, tap Bootstrap and confirm the log trail runs `status received … codeLen=6` → `pair start` → `pair success` → `connect KADB` → `bootstrap terminal success … grant=…`, and the row ends on a "ready" state in one attempt.
- Trigger a failure (e.g. glasses briefly unreachable) and confirm the Self-arm row shows a plain-language reason that survives the glasses' later "code expired" / "setup timeout" messages, and that tapping Bootstrap again is not blocked by a stale in-flight flag.
- Confirm the Self-arm row and notice line read in plain language throughout, never raw codes like `opening_developer_options` or `wireless setup timeout`.

## Device Smoke

- Built and installed the phone APK on the physical test phone (Samsung S23+) with the RG glasses connected.
- Verified end to end on the glasses: a single attempt pairs, connects, and grants `WRITE_SECURE_SETTINGS`; the bootstrap reports complete and self-arm auto-provisions.
- Rebooted the glasses and confirmed the recovery bridge survives with no ADB and no app interaction: `WRITE_SECURE_SETTINGS` still granted, the Relay Accessibility service re-binds on boot (capabilities 43).
