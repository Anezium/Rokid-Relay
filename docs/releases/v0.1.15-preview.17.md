# Rokid Relay v0.1.15-preview.17

Release type: preview reliability update
Date: 2026-07-03

## Highlights

- Hardens the phone bridge arming path: CXR-L link callbacks and bridge state changes are now serialized on the main thread, and a bootstrap epoch guard prevents stale bootstrap threads from overwriting bridge state after a stop, reconnect, or restart.
- Makes the armed state visible and truthful when opening the phone app: the `Relay service` row now reflects the live bridge snapshot (`Operational`, `Connected, preparing glasses app`, `Running, …`, `Armed`, `Stopped`) instead of only the armed preference.
- Adds a `Relay recovery` row with a `Relaunch` action that cleanly restarts the Relay service and bridge without disarming, for manual recovery when the relay looks wedged.
- Surfaces an armed relay with missing notification access as an explicit amber warning (`Armed, notification access missing`) in both the setup row and the notice text.
- Stops the glasses HUD from showing `connected` on raw SDK link callbacks or repeated bridge starts; it only shows `connected` once the phone answers with its `state` payload, and shows `connecting`/`waiting` before that.
- Removes the ADB recovery key generation side effect from status rendering: `localKeyAvailable()` is now a read-only check, with a regression test proving no key files are created.

## Test Focus

- Arm the relay, toggle glasses Bluetooth off/on repeatedly, and confirm the phone status recovers to `Operational` without stale states.
- Open the phone app while armed and confirm the `Relay service` row matches reality (service running, glasses connected, bridge ready).
- Tap `Relaunch` while the relay is armed and confirm the bridge restarts and returns to `Operational` without disarming.
- Revoke notification access while armed and confirm the amber `Armed, notification access missing` warning appears.
- On the glasses, confirm the HUD stays on `connecting`/`waiting` until the phone bridge is actually ready, then shows `connected`.
