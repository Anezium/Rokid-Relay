# Rokid Relay v0.1.15-preview.24

Release type: preview diagnostics
Date: 2026-07-07

## Why

Issue #4's device still fails self-arm bootstrap on preview.23, and the phone log
only shows `Wireless ADB bootstrap failed: Wireless Debugging pairing failed:
connection closed`. That message is **not** the failure of the new preview.23
self-pairing path — it is the *legacy phone LAN fallback* failing afterwards.

The real sequence is:

1. The glasses run the new on-device self-pair over `127.0.0.1` (`SelfArmLocalAdbBootstrapper`).
2. That self-pair throws, the glasses show the `Phone fallback pairing` HUD, and they
   hand the pairing code back to the phone.
3. The phone runs its old same-network pairing, which cannot reach the glasses across
   the LAN, and reports `connection closed`.

Until now the glasses never told the phone *why* step 1 failed, so we were debugging
blind against the wrong (fallback) error.

## What changed

- The glasses now send their full on-device self-pair failure detail to the phone in
  the `self_pairing_failed` status (`errorMessage`), walking the exception cause chain
  so the underlying KADB/socket reason is never dropped behind a wrapper.
- The phone stores that reason in a dedicated field and renders it as its own
  `Self-pair (glasses):` line in the Diagnostics "Last activity" panel. It is not
  overwritten by the subsequent LAN fallback error, so both are visible at once.
- Self-pair stages are now tagged in the error text so the failing step is obvious:
  `connect probe failed on 127.0.0.1:<port>`, `grant shell failed with exit <n>`, and
  `connect to 127.0.0.1:<port> failed`.
- The phone's own self-arm failure messages now include the full cause chain, not just
  the top-level message.

## How to test (issue #4)

1. Install this APK.
2. Connect the **glasses** to any Wi-Fi (any network, no internet needed).
3. Open Rokid Relay, tap **Bootstrap** on the Self-arm recovery row, keep the glasses awake.
4. If it still does not complete, open **Show diagnostics** and send a screenshot of
   the **Last activity** block. The new `Self-pair (glasses):` line now carries the real
   reason the on-device pairing failed — that is what we need to fix it for good.
