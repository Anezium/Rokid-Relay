# Rokid Relay v0.1.15-preview.20

Release type: preview fix
Date: 2026-07-05

## Highlights

- Fixes Cantonese (and any other language your phone's speech services partially cover) with the Android CXR engine by walking speech **recognizers**, not just locale tags. Since v0.1.15-preview.9 the app always picked the first Google recognition service on the phone; on many devices that is Android System Intelligence (`com.google.android.as`), an on-device-only recognizer with no Cantonese models, so every Cantonese locale was rejected with `Speech language not supported` no matter which tag was sent. Versions before v0.1.8 used the phone's default recognizer — which is why they worked — and preview.9 unintentionally regressed that.
- The app now builds an ordered list of recognizer targets and tries them in turn: the system-default service when it is a Google one (on most phones this is Google's online-capable recognizer), then the other Google recognition services, then the on-device recognizer, then the system default as a last resort. For each recognizer the language's locale chain (`yue-Hant-HK` → `yue-HK` → `zh-HK` for Cantonese) is walked first; when a recognizer rejects every locale, the next recognizer is tried. Rejections are instant, so the walk adds no noticeable delay.
- Transient recognizer errors keep both the recognizer and the locale that were in use; nothing falls back to the system language mid-session.
- Each attempt is logged (`Android CXR recognizer attempt target=… tag=…`) so reports can show exactly which recognizer handled a session.

## Verification

- On a Hong Kong OPPO (Android 16, the reporting user's device), the on-screen speech diagnostic confirmed the exact failure and the fix path: `com.google.android.as` and the on-device recognizer reject every Cantonese locale (error 12), while the default Google recognizer transcribes Cantonese on all three locales — in Traditional Chinese, including the no-hint case (「冇問題」).
- On a Samsung S23+ the default service is also Google's online recognizer; a live glasses voice reply through the new ordering transcribed correctly from the glasses microphone, confirming the default recognizer honors the injected glasses audio stream (the concern that motivated the preview.9 recognizer preference).

## Test Focus

- Cantonese: set Speech language to 廣東話, use the Android CXR engine, send a glasses voice reply in Cantonese — expect Traditional Chinese output, not Simplified, not Mandarin, no `Speech language not supported`.
- Any language: confirm voice replies still transcribe from the glasses mic (not the phone mic) and that Auto behaves as before.
