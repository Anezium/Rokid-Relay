# Rokid Relay v0.1.15-preview.10

Release type: preview hotfix
Date: 2026-06-28

## Highlights

- Fixes the Android CXR language-code failure path found on a Samsung Android 36 phone with Google `SpeechRecognizer` and injected CXR audio.
- Forces Android CXR back to transcription language `Auto` and disables the other language chips while Android CXR is selected.
- Keeps explicit language selection available for API speech engines, where the provider-specific OpenAI, ElevenLabs, and Azure codes are still useful.
- Coerces stale saved Android CXR language preferences back to `Auto` at UI render time and before voice capture starts.
- Adds a debug-only SpeechRecognizer language probe for repeatable support-check and injected-audio `startListening()` testing.

## SpeechRecognizer Note

Runtime testing showed `checkRecognitionSupport()` was too weak for this case: it reported support even for an invalid control tag. The stricter `startListening()` probe with `EXTRA_AUDIO_SOURCE` confirmed explicit tags such as `zh-HK`, `zh-TW`, `zh-CN`, `yue-Hant-HK`, `cmn-Hant-TW`, and `cmn-Hans-CN` can return `ERROR_LANGUAGE_NOT_SUPPORTED` or `ERROR_LANGUAGE_UNAVAILABLE`.

For Android CXR, this preview treats auto-detection as the only supported language mode. API speech engines keep the existing language selector.

## Test Focus

- Select `Android CXR` in the phone Speech panel and confirm only `Auto` remains enabled in the language grid.
- With an old saved non-Auto language preference, open the phone app and confirm Android CXR resets it to `Auto`.
- Start an Android CXR reply from the glasses and confirm the old `Speech language not supported` failure no longer appears for selected-language reasons.
- Regression-test one API speech engine with an explicit language to confirm the selector still works outside Android CXR.
