# Rokid Relay v0.1.15-preview.23

Release type: preview feature
Date: 2026-07-06

## Highlights

- The glasses now pair Wireless Debugging with themselves, on the glasses, over `127.0.0.1`. The phone no longer has to reach the glasses across the local network to arm self-arm recovery. This removes the entire class of "Phone and glasses must be on the same Wi-Fi / could not reach glasses pairing endpoint" failures — VPNs, client isolation, carrier/hotspot NAT, or simply being on different networks can no longer block the first-time setup.
- Because the pairing connection never leaves the glasses, the phone's own network is now irrelevant to bootstrap. The old "connect this phone to Wi-Fi first" requirement is gone from the main path.
- The only remaining network requirement is that the **glasses** are connected to some Wi-Fi network — any network, no internet needed. Android only exposes Wireless Debugging while Wi-Fi is on. If the glasses have no Wi-Fi, the app now says so explicitly.
- The legacy phone-driven pairing path is kept as an automatic fallback: if on-glasses self-pairing ever fails, the glasses hand the pairing code back to the phone and the old same-network flow runs exactly as before. Older glasses builds that predate self-pairing continue to work unchanged.

## How it works

- When the glasses reach the Wireless Debugging pairing dialog, they read the live pairing code and port and run an ADB pairing handshake against their own on-device `adbd` over `127.0.0.1`, then connect locally and grant themselves `WRITE_SECURE_SETTINGS`. That grant is what lets the app repair its own accessibility access afterwards, so it is done once and persists.
- The phone waits while on-glasses self-pairing is in flight and no longer starts a redundant, doomed connection attempt of its own across the LAN.

## Verification

- The on-glasses self-pairing chain was exercised end-to-end on real hardware: the automator reached the pairing dialog, paired over `127.0.0.1`, and `WRITE_SECURE_SETTINGS` came back `granted=true` and persisted. The phone accepted the glasses-reported completion.
- The removal of the phone Wi-Fi requirement was confirmed on-device with the phone's Wi-Fi turned off: the bootstrap flow started and ran with no "connect this phone to Wi-Fi" block.
- Both APKs build and the phone unit tests pass.

## Test Focus

- First-time self-arm setup on a device where the phone and glasses could not previously reach each other (VPN on the phone, a public/carrier Wi-Fi with client isolation, or phone and glasses on different networks): connect the **glasses** to any Wi-Fi, keep the phone as-is, tap **Bootstrap** on the Self-arm recovery row, and expect it to complete without the "same Wi-Fi / could not reach glasses" error.
- Confirm the grant sticks: after a successful bootstrap, self-arm recovery should stay armed across a glasses reboot with no further pairing.
